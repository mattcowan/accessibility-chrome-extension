Live Regions (aria-live) Monitor Fixtures

Fixtures for the Live regions monitor (WCAG 4.1.3 Status Messages). Start the monitor from the extension popup, then use the buttons below — each announcement must appear (appended, never replacing earlier entries) in the on-page log panel attached to its region. data-expect="review" regions must get a panel and a start-time finding; data-expect="pass" must be ignored.

⚠ Review (a): aria-live="polite"

⚠ Panel should show a green "polite" tag; each click appends a new entry.

⚠ Review (b): aria-live="assertive"

⚠ Panel should show a red "assertive" tag.

⚠ Review (c): role="alert" (implicit assertive)

⚠ No aria-live attribute — implicit assertive via role.

⚠ Review (d): role="status" (implicit polite)

⚠ Removing the region must keep its panel (marked "removed") and its logged entries must survive in the export.

⚠ Review (e): <output> (implicit status)

⚠ The output element has an implicit status role — polite.

⚠ Review (f): aria-atomic="true"

Cart total: $0.00

⚠ Only one span mutates, but aria-atomic means the whole region is announced — the logged message must contain the full "Cart total: $…" text.

✓ Pass (g): aria-live="off"

✓ aria-live="off" must get no panel and no finding.

Dynamic behaviors

"Add dynamic region" creates a new polite region after the monitor started — it must get a panel (no retroactive finding; badge counts start-time regions). "Rapid duplicate ×3" writes the identical message three times within ~100 ms — dedupe must collapse it to one log entry. The interval announcer posts a counter to the polite region every 3 s for soak testing.
